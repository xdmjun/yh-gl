# 资源受限 AI 协同开发方法论 · 体系全景与跨项目使用指南

> 用途：本文件是 v1/v2/v3 三份手册的**总导读**——一页看清体系包含什么、涉及哪些文件、流程怎么咬合、新项目按什么步骤接入。细节以三份手册原文为准。
> 版本：1.0
> 性质：方法论总结文档；示例为实践抽象，CBM、控制工具等均未随手册实现。

## 0. 范式卡

**一句定位**：资源受限下的 AI 协同开发方法论——流程强度匹配任务风险（应化），一切结论以可追溯证据为准（知不知），每个环有出口（知止），人保留目标与决议权。

**六层栈**：炁（资源与额度）→ 势（限流等外部环境，顺应不对抗）→ 器（确定性工具）→ 术（验证环、拆批、波次）→ 法（分级、契约、底线）→ 道（第一性原则与人权边界）。每层的机制锚点见 v2 §2.1。

**思想原则 → 机制对照（术语谱系）**：

| 原则 | 出处 | 编译为 |
|---|---|---|
| 应化 | 道家"应物变化" | v2 §5.1 分级优先级规则 |
| 知不知 | 《道德经》71 | v2 §7.2 未知清单证据状态机 |
| 知止 | 《道德经》32/44 | 任务包 stop_on + v2 §9.4 失败路由 |
| 观复 | 《道德经》16"吾以观复" | v2 §10 流程改进环 |
| 聚散有时 | 道家"应时聚散" | v2 §8.3 角色激活与释放 |
| 损之又损 | 《道德经》48"为道日损" | v2 §10"无收益则撤回" |
| 虚室生白 | 《庄子·人间世》 | 上下文装载三律（v2 §6.2） |
| 名实相符 | 《荀子·正名》"制名以指实" | v1 §4.3 本体先于契约 |

**与相邻范式的差异**：对纯 SDD，Spec 降为验收依据、不充当任务清单，任务由数据流切分（v3 §1）；对单 Agent 自主流，机器只承接机械判断与证据执行，判断权在人；对传统 PM，工作包等概念同构，但以额度与证据约束重构——分级决定流程强度，指标是安灯不是 KPI。

**编译律（术语纪律）**：每个思想名词必须编译为至少一条可检验规则或一个命名产物，编译失败即降为出处注脚；思想名词止于上表，不再新增。

### 1.1 文件清单与职责

| 文件 | 层级 | 核心内容 |
|---|---|---|
| `01-v1-理念层-通用指南.md` | v1 理念 | 五类资产（规格/决议/代码图/任务图/验收证据）各有唯一事实源；六项升级（验证下沉/图查询下沉/任务 DAG/决议关联/限流调度/失败熔断）；全生命周期 SOP；四模板（启动卡·任务包·验证报告·窗口指令）；轻量/标准/加强三档；提效衡量口径；反模式与底线 |
| `02-v2-机制层-实施手册.md` | v2 机制 | 项目接入五份记录；需求→任务三门槛；应化分级（风险 R/不确定性 U/耦合 C/资源 B → H1/H2/H3 配方）；CBM 接入七步验收表；任务包 JSON（含未知清单证据状态机 confirmed/inferred/unknown/conflict）；单写者派单与 READY 判定；验证环九步 + 失败路由表 + 报告状态机（PASS/FAIL/SKIP/BLOCKED/TIMEOUT/CANCELLED/NOT_RUN）；流程改进环（改进卡）；控制 CLI 契约与验收集；P0~P5 计划；可直接粘贴的 AI 接入指令 |
| `03-v3-调度层-滚动交付手册.md` | v3 调度 | Spec 降为规范事实源、数据架构升为拆分依据；五步拆分模型（数据流矩阵→类型化依赖边→用户故事切批→批内波次→门禁）；契约分层 L1~L4 + 通用填空模板 + 按项目形态裁剪表；CBM 波级校验点（矩阵偏差数指标）；Mock 出现率指标（稳态趋零）；多窗口波次切换；风险护栏 |
| 项目规则文件（每个项目自定名，如 AGENTS.md / RULES.md） | 实例 | L1 契约填空示范：技术栈版本表（事实源 = 依赖清单/lockfile）、环境约束、端口分配、变更规则 |

## 2. 流程主链：三层如何咬合

```
需求澄清 → 设计/契约冻结 → 拆分 → 分级 → 派单 → 实现 → 验证 → 交付 → 集成/验收 → 复盘
    │           │             │        │        │       │        │        │          │          │
  人的职责  L3契约+L1环境   v3数据流  v2应化   v2单写者  v2定向  v2验证环  v2报告   v3批次门禁   v2改进环
            (v3§2.7)      五步拆分  R/U/C/B  READY判定  图查询  L1/L2/L3  +diff   +CBM波级校验  (迭代级)
                          (§2.1-5) →H1/H2/H3 (§8.2)   (§6.2)  (§9)    交付      (§2.6)
```

**三档强度（同一主链，伸缩不同；真相源：v2 §2.2/§5.2）**：

| 档位 | 适用 | 跳过 | 不省 |
|---|---|---|---|
| H1 轻量 | 单页面/少量接口/小模块 | CBM、DAG、批次、mock、独立评审、复盘 | 验收断言先行、scope 纪律、真实退出码、commit 授权 |
| H2 标准 | 多模块、多窗口、持续迭代 | 控制工具、请求代理 | 任务包、依赖表、认领、分层验证 |
| H3 加强 | 权限/数据迁移/发布关键路径 | ——（加独立复核与批准） | 全部门禁 |

**升级信号**（小任务出现任一即升档，冻结当前改动、补 5 行最小任务包，不退回重走）：碰公共文件 / 契约两侧对不上 / 动权限逻辑 / 需求说不清"什么算对" / 同一问题修 3 轮没好。

## 3. 在其他项目使用的步骤

### 阶段 0：判断需要哪一层

| 你的情况 | 用什么 | 要建的文件 |
|---|---|---|
| 单人小改动 | 只用 v2 H1 档 | 零 |
| 多模块 / 多窗口并行 | v2 + v3 | 见阶段 1 |
| 全新项目从零启动 | 全套 | 见阶段 1 |

### 阶段 1：项目接入

1. **抄 v3 §2.7.1 的 L1 填空模板** → 写进该项目规则文件；每格标注事实源（依赖清单 / lockfile / 环境样例文件…），**禁止凭记忆填写**；按裁剪表删格（纯客户端删端口表、monorepo 加包间契约、嵌入式换交叉工具链、单人简化 L4）。
2. **按 v2 §3.2 填启动卡**（10 项：目标/权威输入/实现边界/当前基线/工具可用性/环境边界/审批规则/验收定义/资源/集成责任）。
3. **建最小目录**（v2 §3.1）：`docs/workflow/`（checks.json + tasks/）、`docs/decisions/`、`work/workflow/runs/`——运行目录不进 Git。

### 阶段 2：首个试点任务

4. 选低风险任务（v2 §3.3：没有新需求就做**只读验收盘点**——验证一条现有用户路径，只出证据不改代码）。
5. 心算应化分级 → 填任务包（完整 JSON 或 5 行简化版：目标/scope/验收/非目标/未知）。
6. 跑 v2 §9.1 九步闭环：认领 → 核对基线 → 实现 → 冻结输入 → L1 检查 → 真实退出码 → 失败分类 → 交付 diff+报告 → 授权后集成。
7. **试点成功标准**：另一个窗口凭任务包能干活、检查有真实报告、未知和阻塞没被伪装成通过。

### 阶段 3：多模块扩展（出现真实并行需求时）

8. 画**数据流矩阵**（v3 §2.1：表 × 写者/读者/故事；人工策展 + owner 确认，CBM 只做事后校验，不是拆分器）。
9. 按用户故事主线切 4~6 批 → 批内切波次：A（生产方实现 ‖ 消费方接口无关层）→ B（联调串行 + 绑真接口）→ C（下批预开发吃空闲产能）。
10. 接入 CBM（v2 §6 七步验收表），每波次收口跑**波级校验**（v3 §2.6），盯三个指标：

| 指标 | 守什么 | 持续 >0 的含义 |
|---|---|---|
| 矩阵偏差数 | 结构越界 | 矩阵过期或模块边界失守 → 回 Step 1 |
| Mock 出现率 | 下游饥饿 | 预开发产能不足/契约冻结滞后 → 调排布 |
| 批间等待时长 | 瓶颈堆积 | 批次切分倾斜 → 重切批次 |

### 阶段 4：自动化与持续改进（可选）

11. 仅当协调成本确实高时实现 v2 §12 控制工具（`doctor / validate / ready / claim / pack / verify / deliver / accept / report`），并用 11 条验收集测试它（双窗口抢认领、scope 父子包含冲突、非零退出但日志裁剪成功不算 PASS、STALE 报告拒收等）。
12. 每迭代跑一次 v2 §10 流程改进环：观测 → 归因 → 改进卡 → 限定试点 → 对照收益 → 固化或撤回。**对手册自身提出的指标也一样**——Mock 出现率、矩阵偏差数若与返工/等待不相关，就撤掉。

## 4. 契约分层速查（跨项目最常用的决策表）

| 下游任务 | 需要的最小契约集 | 依据 |
|---|---|---|
| 消费方界面层（接口无关层） | L3 接口契约（响应形状）+ L1 环境契约（服务地址） | v3 §2.7 |
| 生产方预开发 | L2 组件契约（key 前缀、迁移编号）+ L1 技术栈契约 | 同上 |
| 联调 | L1 环境契约（端口、进程管理）+ L2 部署契约 | 同上 |
| 任何窗口（常驻） | L4 协作契约（scope、授权、熔断） | 同上 |

**核心收益**：下游任务只等它消费的那层契约，不等"所有契约"——分层粒度直接换来并行度。

## 5. 全程不变的底线与退出原则

**底线（任何档位、任何项目不可侵蚀）**：人保留目标与决议权；提交/推送/删除/真实环境操作必须授权；不删测试不弱化断言不造假变绿；预算不足缩小任务而非降门禁；静态图一致性是门禁必要条件而非充分条件（联调与测试照常）。

**退出永远安全**：CBM 可拆（退回 grep/AST）、工具可停（退回单写者登记）、指标可删（退回人工判断）；Spec、决议、验收证据不因退出丢失——它们始终在普通文档和 Git 里。
