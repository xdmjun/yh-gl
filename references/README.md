# 应化 Graph-Loop · AI 协同开发方法论

资源受限条件下，用 AI 协同做软件开发的方法论，三层递进：**v1 理念 → v2 机制 → v3 调度**，[00-总导读](00-总导读.md) 负责体系定位与接入步骤。

## 这个目录是什么

四份手册，没有外部依赖即可完整运行：

- **不依赖 CBM** —— 有则加速，无则退回 grep/AST，流程不塌
- **不依赖控制工具 CLI** —— 有则自动化，无则单写者登记 + 人工检查

本目录同时是一个 agent skill：`SKILL.md` 为路由层，四份手册与 README 在其 `references/` 下。方法论经 skill 分发，项目侧不存放手册副本。

## 接入新项目

1. **确认宿主已安装 yh-gl skill**（项目侧不存放手册副本）
2. **写 L1 契约填空表** 到项目规则文件（模板见 [v3 §2.7.1](03-v3-调度层-滚动交付手册.md)）
   - 每格标注事实源（依赖清单 / lockfile / 环境样例）
   - **禁止凭记忆填写**
   - 按项目形态裁剪：纯客户端删端口表、monorepo 加包间契约
3. **填一张启动卡**（10 项，模板见 [v2 §3.2](02-v2-机制层-实施手册.md)）
   - 目标 / 权威输入 / 实现边界 / 当前基线 / 工具可用性
   - 环境边界 / 审批规则 / 验收定义 / 资源 / 集成责任
4. **选一个低风险任务试点**（模板见 [v2 §3.3](02-v2-机制层-实施手册.md)）
   - 没新需求就做「只读验收盘点」：验证一条现有用户路径，只出证据不改代码
5. **试点成功标准**：另一个窗口凭任务包能干活；检查有真实退出码；未知和阻塞没被伪装成通过
